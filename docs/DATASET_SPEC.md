# 数据集与形式规约说明

## 范围和构成

数据集包含题库 PDF / JSON 中的全部 20 道公开题，以及 10 道原创合成题，共 30 道。公开题难度保持题库原标签（6 道 Easy、8 道 Medium、6 道 Hard）；自建题覆盖 4 道 Easy、4 道 Medium、2 道 Hard。每题记录要求、可读接口信息、来源、适配说明、显式假设、scan-level LTL 性质和测试场景。机器可读主文件为 `dataset/tasks.json`。

公开题原始内容保存在 `dataset/question_bank_original.json`，来源文件为随作业提供的 `大作业题库.pdf` 与 `大作业题库json.zip`。本项目保留原题文字，不声称这些材料来自本组原创。接口从原 JSON 的表格中解析；对 VARIANT、开放数组等目标平台相关类型，模型必须指出平台限制，不得自行假定可编译。10 道合成题的规范源记录保存在 `dataset/synthetic_tasks.json`，`dataset/build_dataset.py` 从随包原始材料和该文件重建 `dataset/tasks.json`。

## 自建题来源、生成和人工审查

S01–S10 均为原创合成题，没有复制在线题目段落。生成过程为：先选取常见离散控制场景（泵、输送线、储罐、批次混料、风机、压缩机、安全门、剔除机构、双罐转输、温控），再组合有限状态、联锁、延时、故障和复位行为；随后写出接口、状态边界、复位条件、优先级与不少于四个边界测试场景。人工审查逐题核对：输出是否在安全条件丢失时进入安全态、复位是否需要显式条件、边界值是否有定义、测试是否覆盖正常和故障路径、LTL 是否与文字要求一致。S07 中的普通 PLC 逻辑输出仅用于课程建模，不能代替经认证的安全回路。

## 多样性与难度口径

任务按状态复杂度而不是代码长度标注难度。Easy 主要考察单状态、边沿、回差、计时或明确联锁；Medium 加入多阶段顺序、数组/数值转换、故障恢复或模式；Hard 涉及动态流程/数据结构、循环队列、跨阶段自动化或多个状态不变量。题库自身难度标签保留；自建标签只用于分层抽样，不作为独立客观难度真值。覆盖维度包括布尔联锁、边沿、定时器、数值边界、数组、模式、状态机、故障锁存、计数/历史和字符串解析。

## LTL 语义和限制

每个轨迹位置由本次扫描开始采样的输入，以及该扫描结束时的输出和状态组成。`prevX` 指上一扫描的值。累计量用当前值与上一扫描值比较，运行时加本次 `CycleTime`，停机时保持。`X` 指下一轨迹位置，不能用 `X(total = total + dt)` 表示累计，因为等式两边都会指向下一位置。`G` 表示始终，`F` 表示最终。立即联锁用同一扫描输出表达。涉及自动阶段的规则必须含模式与阶段条件，急停优先级在相应前件中明确体现。

比较式、位运算、数组元素、状态与计时器完成标志是数据谓词。P04 的 `prevPumpRuntime` 和 P12 的 `prevSlabRuntime` 在首扫描前均初始化为零。`AND_i`、`popcount`、`validIPv4` 等记号需要绑定实际变量并按求解器语法展开。

标准 LTL 不直接表达毫秒/秒的物理时长，因此定时性质使用显式谓词（例如 `T5s`、`hold500msDone`）表示 TON/累计时间达到阈值。`F` 不给出有界时间保证；凡题目要求“立即”，以同一扫描安全约束表达；凡题目要求定时，另由定时器状态及测试向量核对。数据文件内每个公式是设计规约，尚未宣称已由 PLCverif 解析或证明。

对原题未定义的部分（边沿/电平触发、初值、相同优先级、超范围值、模式切换、多个同时请求），在对应 `assumptions` 中固定语义。此举使两框架获得完全相同输入定义和判分标准。任何正式编译或验证都必须固定 CODESYS / IEC 61131-3 目标 profile，并记录编译器诊断及 verifier 版本。

## 测试向量

v1.1 修订了 19 道题的规约或相关说明。对应的边界场景包括 P04 从 0 累计到 50 ms、100 ms，停机后保持 100 ms；P12 在有效且无故障时累计，信号无效后保持；P07 手动允许四台选中泵运行，自动只选排名前三；P20 手动前进时允许工位传感器保持置位，自动洗涤完成后允许向下一工位移动。v1.2 修正 P08 无效模式与量程检查的优先级、P17 请求边沿与并发拒绝条件，以及 P18 同一扫描中队列操作前后的计数语义。

每题的 `test_cases` 给出可复现的场景描述和期望结果。数值映射、计时边界、优先级、故障态和复位条件均纳入测试。可执行向量位于 `tests/structured_text/runtime_suites/`。逐场景实际执行情况见 [IDE 模拟复测记录](../experiments/ide_simulation_review/README.md)。P13 使用模拟设备时钟采样，S08 的饱和场景由驱动把计数器预置到 UDINT 最大值后验证新的有效边沿。
